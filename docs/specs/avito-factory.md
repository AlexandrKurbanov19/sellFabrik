# Спецификация: софт «Avito-фабрика»

Автоматизация воспроизведённого пайплайна: анализ конкурентов → тексты → фото → рандомайзер →
фид → Avito Автозагрузка → продвижение → переадресация звонков в Leads Market → аналитика.

> **Юридическая оговорка.** Мультиаккаунтинг и дубли объявлений нарушают правила Avito.
> Блокировки — ожидаемая издержка. Юрлицо/договоры и обработка ПД (152-ФЗ) — зона ответственности
> владельца. Этот документ описывает **автоматизацию процесса**, а не обход закона.

---

## 1. Референс-пайплайн (как это делают сейчас)

1. Анализ **топ-3–5** в выдаче по направлению.
2. Написание **своего текста** под направление.
3. Генерация **уникальных фото** (Grok / Nano Banana) → очистка метаданных → смена разрешения/наклона,
   чтобы одну картинку размножить на много объявлений.
4. **Рандомайзер**: готовые текст+фото → набор уникальных объявлений.
5. **Умножение** на направления × города (≈2270 пар из `pulse.xlsx`).
6. Выгрузка **через Excel/фид в Avito Автозагрузку**.
7. **Продвижение** каждого объявления.
8. Клиент звонит на **электронный номер с нашим партнёрским ID** → переадресация в колл-центр Leads Market.

## 3. Модули

### M1. Анализатор конкурентов
- **Вход:** направление (+ город опционально).
- **Действие:** спарсить топ-3–5 объявлений (заголовок, текст, цена, услуги, число фото, стиль).
- **Инструмент:** Playwright в антидетект-профиле (или сторонний парсер) — выдача Avito рендерится JS.
- **Выход:** `CompetitorAd[]` + **бриф** (что заходит: структура заголовка, УТП, цены, оффер).
- **Хранение:** Strapi `competitor-ad` + `content-brief`.

### M2. Генератор текстов
- **Вход:** бриф M1 + карточка направления.
- **Действие:** LLM генерирует **N заголовков × M текстов** на направление; уникализация
  (синонимы, порядок блоков, CTA, вставка города, блок «что не делаем» из стоп-факторов).
- **Выход:** `AdText[]` с контролем схожести (по n-граммам), чтобы тексты не дублировались.
- **Инструмент:** LLM API (Claude/GPT/Gemini) + шаблоны промптов на направление.

### M3. Генератор и уникализатор фото
- **Шаги:**
  1. Генерация базовых фото через **Nano Banana** (`gemini-2.5-flash-image`, ~$0.02–0.04/шт)
     или Grok; либо реальные фото.
  2. **Удаление метаданных** — `sharp` (по умолчанию чистит EXIF) или `exiftool`.
  3. **Вариативность** на K копий: crop, поворот на 1–3°, ресайз/аспект, яркость/контраст/тон,
     лёгкий шум/резкость, перекодирование.
  4. Контроль **перцептивного хеша** (pHash) — не допускать близких картинок в одном аккаунте.
- **Выход:** `AdImage[]` (база + варианты) в S3.
- **⚠️ Риск:** Avito сравнивает не только EXIF, но и **визуальный отпечаток**. Простая
  перекодировка/наклон может не пройти. Нужны **разные сцены** (несколько баз на направление) +
  геометрические/фотометрические вариации. AI-фото могут выглядеть «зализанными» → падение конверсии;
  держать пул реальных фото как приоритетные.

### M4. Рандомайзер / ассемблер
- **Действие:** декартово произведение `направление × город × заголовок × текст × набор фото`.
- **Правила:** не повторять комбинацию внутри аккаунта; равномерно распределять; город — в заголовке
  или первом абзаце; персональный CTA.
- **Выход:** `Ad` (готовая единица объявления), привязанная к аккаунту.
- **Хранение:** Strapi `ad` + внешний ID для Avito.

### M5. Генератор фидов
- **Действие:** маппинг `Ad` в шаблон категории **«Услуги»** Avito.
- **Форматы:**
  - **XML** под Автозагрузку (основной, официальный);
  - **Excel/XLS** по скачанному в кабинете шаблону (как делают знакомые).
- **На аккаунт** — свой фид, с учётом **лимитов** подкатегории и тарифа.
- **Поля:** `Id` (внешний), `Category/Subcategory`, `Title`, `Description`, `Price`, `Images[]`,
  `City/Geolocation`, `DateBegin`, контакты (наш номер).
- **Endpoint:** `/feed/:accountId.(xml|xls)`.

### M6. Менеджер аккаунтов и инфраструктуры
- Сущности: `Account` (антидетект-профиль, тариф, лимит, статус жив/бан), `Proxy` (мобильный,
  город = город объявления), `Phone` (SIM/электронный номер).
- **Прогрев** свежих аккаунтов по расписанию (активность до залива).
- **Распределение** объявлений по аккаунтам с учётом лимитов.
- **Мониторинг банов**: статусы объявлений через Avito API/парсинг → пауза, перелив бюджета,
  замена аккаунта.

### M7. Менеджер продвижения
- Применение платных услуг к объявлениям (Avito API «платные услуги»).
- Бюджет на `направление × город × аккаунт`; авто-пауза убыточных связок.
- Учёт **расхода на объявление** → CPL.

### M8. Роутинг лидов
- **Звонки:** электронный номер (в объявлении) + **партнёрский ID** → переадресация в колл-центр
  Leads Market. Один номер = одна точка атрибуции (нужно решить: номер на аккаунт / направление / город).
- **Чаты:** нужно уточнить механику (кто отвечает в чате Avito) — либо оператор, либо интеграция
  с чатом партнёрки.
- **Хранение:** `Lead` (звонок/чат, ad, номер, статус, выплата).

### M9. Аналитика
- **Метрики:** объявления, показы, контакты, CPL, лиды, апрув, доход, расход, чистая прибыль.
- **Разрезы:** `направление`, `город`, `аккаунт`, `номер`, `дата`.
- **Здоровье:** доля банов, срок жизни аккаунта, стоимость замены.
- **Дашборд:** Next.js.

## 4. Модель данных (Strapi)

| Коллекция | Ключевые поля |
|---|---|
| `direction` | code, name, slug, стоп-факторы, шаблоны |
| `city` | name, departmentId, parent, isSatellite |
| `availability` | direction, city, status (из pulse) |
| `competitor-ad` | direction, город, текст, цена, ссылка |
| `content-brief` | direction, выводы, УТП |
| `ad-text` | direction, заголовок, тело, схожесть |
| `ad-image` | direction, s3url, pHash, isBase |
| `ad` | direction, city, account, title, body, images, externalId, status |
| `account` | логин, профиль антидетекта, прокси, телефон, тариф, лимит, статус |
| `proxy` | тип, город, endpoint |
| `feed` | account, формат, url, generatedAt |
| `lead` | ad, type(call/chat), phone, affiliate, status, payout |
| `payout` / `expense` | affiliate/канал, сумма, период |

## 5. Стек

- **Strapi v5 + PostgreSQL** — данные и админка.
- **Next.js** — дашборд и публичные страницы (если нужны).
- **Node/TS воркеры + BullMQ/Redis** — пайплайн (генерация, фиды, мониторинг).
- **S3** — фото; **sharp** — обработка/очистка; **pHash** — контроль дублей.
- **Playwright** (+ антидетект) — парсинг конкурентов и статусов.
- **Gemini Image (Nano Banana)** / Grok + LLM API — фото и тексты.
- **Avito**: Автозагрузка (XML/Excel) + API (объявления, статистика, платные услуги).
- **Деплой:** VPS для воркеров + Vercel/свой для Next.

## 7. Экономика (каркас расчёта)

`Прибыль = Σ (подтверждённые лиды × выплата) − (продвижение Avito + аккаунты + прокси + номера + AI)`

- CPL Avito (ремонт): **320–600 ₽**; выплата LM: **600–1200 ₽**.
- Ориентир пользователя: «чистыми» ≈ 50% от «грязи».
- Ключевые рычаги: **доля апрува**, **цена аккаунта/прокси**, **CPL по городу**, **скорость ответа**.

## 8. Риски

| Риск | Митигация |
|---|---|
| Баны/теневые баны | запас аккаунтов, прогрев, авто-замена, распределение |
| Детект дублей фото (pHash) | несколько сцен на направление + сильные геом./фотометр. вариации |
| AI-фото отпугивают клиентов | пул реальных фото, AI — как дополнение |
| Лимиты/тарифы Avito в Услугах | планировать число аккаунтов и бюджет продвижения |
| Чаты не покрыты | определить механику чата до масштаба |
| Зависимость от Leads Market (апрув/выплаты) | быстрый переход на альтернативу (см. `research/alternatives.md`) |
| 152-ФЗ | согласие, политика, минимизация ПД |

## 9. Открытые вопросы

1. **Номер:** кто провайдер электронного номера, как LM привязывает партнёрский ID, можно ли
   завести **несколько номеров** (на аккаунт/направление/город) для точной атрибуции.
2. **Чаты:** кто отвечает в Avito-чате и как он попадает в LM.
3. **Выгрузка:** точный способ — **XML Автозагрузка** или **Excel-шаблон**; аккаунт бизнес или частный;
   ID категорий/подкатегорий «Услуги».
4. **Аккаунты:** покупаем «броне» или греем свои; сколько в месяц уходит на баны.
5. **Бюджет** на продвижение Avito на первое направление и целевой CPL.
6. **Приоритет:** сначала 1 направление для проверки экономики или сразу 3–5.
